# Implementation prompt: Remove duplicated key points from seeded lesson notes

## Goal
Every seeded lesson's `notes` repeats its `keyPoints` as an h2 "What this lesson covers" plus a bullet list, so the lesson page shows the list twice. Remove that h2 and those bullets from the seed file and from the live dataset. Also explain the `?t=90` rendering report.

## Skills / docs read
- `AGENTS.md` (§8, §12, §13), `sanity-best-practices` (patching documents, `sanity exec` with the user token).
- `prompts/seed-sample-content.md` (how the seed is fixed and imported).

## Code / data inspected
- `studio/scripts/seed/seed.ndjson`: all 120 lessons share the same notes shape: `[intro paragraph, h2, bullet, bullet, bullet, closing paragraph]`. In all 120, the bullet text equals `keyPoints` exactly.
- `studio/scripts/seed/fix-seed.mjs`: the existing idempotent "bring seed in line" transform.
- `studio/package.json`: `seed:import` = validate, then `sanity dataset import --replace`.
- `components/lesson/lesson-notes.tsx`: the intro paragraph becomes the lesson subtitle and the rest renders as Overview. After the fix, Overview is the closing paragraph only.

## `?t=90` report (no code change)
The server returns the correct page for `?t=90`. The YouTube iframe is in the HTML with `start=90`, and the CSS served now contains `aspect-video`, `size-14`, `gap-x-8` and the `prose` styles. The screenshot is missing exactly those styles (no video height, no course icon, no meta gaps, unstyled notes). So the browser tab held a stylesheet compiled before the typography plugin was added. The red Next.js badge errors come from the React DevTools extension, not the app. Fix: hard reload (Ctrl+Shift+R), or restart `next dev` if it persists.

## Decisions
1. **Seed file**: add an idempotent step to `fix-seed.mjs`. For each lesson, drop an h2 block whose text is "What this lesson covers" and the bullet blocks that follow it, but only when those bullets equal `keyPoints`. Otherwise leave the lesson untouched and log it. Then rerun `fix-seed.mjs` and `seed:validate`.
2. **Live dataset**: patch only `notes` on the affected lessons with a small `sanity exec` script (`studio/scripts/seed/dedupe-notes.mjs`, run with `--with-user-token`), using the same matching rule. I am **not** using `seed:import --replace`, because it would overwrite whole documents and wipe any edits made in Studio since the seed. The script reads published lessons, builds the new notes, and commits one transaction. Running it again is a no-op.
3. Keep the intro paragraph (the subtitle) and the closing paragraph (Overview). Nothing else changes.

**Deviation during implementation:** `fix-seed.mjs` can no longer run, because it copies course icons from `public/courses/`, which no longer exists, and rerunning it would also overwrite the icon SVGs. So the seed-file transform lives in `dedupe-notes.mjs --file` instead, sharing the same matching rule as the live patch. `fix-seed.mjs` is unchanged.

## Security considerations
- The patch uses the logged-in Sanity CLI session (`--with-user-token`). No token is written to disk or printed. The dataset stays private.
- It writes only `notes` on `lesson` documents, and only where the h2-and-bullets pattern matches the lesson's own `keyPoints`.

## Acceptance criteria
- `seed.ndjson`: 0 lessons with a "What this lesson covers" block. Every lesson's notes = intro + closing paragraph. `seed:validate` passes.
- Live: `count(*[_type=="lesson" && "What this lesson covers" in notes[].children[].text])` returns 0. Lesson count stays 120, and keyPoints are unchanged.
- The lesson page shows the key points once (under "In this lesson you will:") and Overview shows the closing paragraph.
